# グローバル寓話大富豪 〜世界童話経済すごろく〜 設計書

世界中の童話キャラクターが現実の世界地図を旅し、物件を買い漁り、風刺ニュースに振り回されながら大富豪を目指す経済すごろく。PC / スマホのブラウザで CPU・ローカル（同じ端末を回す）・オンライン（最大4人、別端末）対戦。

この文書が実装の正本。型の正本は `src/core/types.ts`、通信の正本は `src/net/protocol.ts`。

## 1. 技術構成

### 1.1 オンライン前提の設計（ホスト権威 P2P 方式）

ユーザー決定（2026-11-23）: 専用サーバーを持たず、`nanj-kakutougi` と同じく公開 MQTT ブローカー + WebRTC で通信し、GitHub Pages で公開する。

- **ゲーム状態の正本はホスト端末の `RoomController` だけ**。ゲストは `Action` を送り、ホストが `step()` で検証・適用し、`fx` と新しい状態を全員に配信する。ゲストは状態を予測しない。ホスト自身もループバック接続の 1 プレイヤー。
- **乱数はホスト内**（`state.rng`, mulberry32）。配信時に `rng` を取り除く（`sanitizeState`）。ゲストがサイコロを決めることはできない。既知の限界: ホスト本人は乱数を知り得る（友人同士のプライベートルーム前提で許容。公開マッチングで問題になれば専用サーバー版 `RoomController` を同じプロトコルで立てられる）。
- 不正・競合対策: 行動は「今行動すべき席の持ち主」からだけ受け付ける。各メッセージは `seq` を持ち、古い `seq` は `stale` で拒否（二重タップ・同時操作・再送を無害化）。ホスト内で処理は直列。
- **ローカル / CPU 対戦も同じ `RoomController` をブラウザ内で動かす**（`LocalSession`）。オンラインとローカルでルール・CPU・タイマーの経路が一つ。
- 秘匿: MQTT のトピック名はルーム ID のハッシュ、本文はルーム ID から導出した鍵で AES-GCM 暗号化（公開ブローカーのワイルドカード購読者に中身を読まれない）。
- 再接続: 端末ごとの `clientId`（乱数、`localStorage`）で同じ席へ復帰し `snapshot` を受け取る。
- **ホスト移譲**: 全員が最新の公開スナップショット（ロビー・状態・seq・チャット）を保持。ホストの心拍が 10 秒途絶えたら、接続中で最小の席番号の人間が新ホストになり、公開スナップショット + 新しい乱数シードで `RoomController` を再構築して続行。旧ホストの席は通常の切断ルールに従う。
- **単一権威の承認**: 各ゲストは同時に 1 人のホスト（公開鍵指紋 + 世代）だけを追従し、生存通知・ack にはその `following` を必ず載せる。ホストは「その最新の生存通知が自分を指している席」だけをクォーラムに数える。権威のクォーラムは**現在人間の席**の厳密多数で、切断 → CPU 置換（120 秒）は凍結中も進むため、置換後は残った人間だけで続行できる。世代は権威交代のたびに `max(既知の世代) + 1` で単調増加し、古い世代の主張は採用しない（必要なら `gen_bump` で現権威に世代更新を要求する）。
- **分断時の残余リスク（許容）**: 完全な対称分断では両側がそれぞれのクォーラムを満たさず凍結するが、120 秒の CPU 置換が双方で進むと両側が続行し得る。復旧時は世代（同世代なら seq・接続人数）で勝敗を決め、**勝った側の状態だけを採用**し、負けた側には「通信が分断されていた間の進行は取り消されました」を表示して破棄する。進行の分岐そのものは防げないため、公開マッチングではなく友人同士のルームを前提とする。
- 放置・切断: 人間の手番には制限時間（既定 30 秒、ルーム設定 20/30/60/無制限）。時間切れ・切断中は CPU ロジックが代行（`autoplay`）。切断後 120 秒戻らなければ席は CPU に置換（資産は維持）。明示的な退出は即 CPU 置換。
- コミュニケーション: §8。
- 公開マッチング拡張: `RoomSettings.visibility = 'public'` のルームは MQTT の公開ロビートピックに定期告知し、一覧から参加できるようにする（初版は private のみ UI に出す）。

## 2. ルール

### 2.1 進行
- 1〜4 人。年数 1/3/5/10/20 年（既定 3 年）。年度は 4 月開始、毎ラウンド（全員が 1 手番）で 1 か月進む。3 月の後に**決算**。
- 開始: 所持金 100 億円、全員同じ開始都市（東京以外も可、既定はランダムな tier1 都市）。最初の目的地を抽選。
- 手番: (カード使用 0〜1 枚) → サイコロ → 移動先を選ぶ → 止まったマスの処理 → 手番終了。`skipTurns > 0` なら手番を飛ばす。
- サイコロ: 通常 1 個（1〜6）。出目ちょうどの歩数で到達できる全マスをハイライトし、プレイヤーがタップで選ぶ。移動中、直前にいたマスへは戻れない（同じ手番で同じ辺の往復禁止）。行き止まりでは折り返し可。
- **目的地を通過・到着した時点で到着扱い**（そこで移動終了）。
- 終了: 最終年の決算後、総資産（所持金 + 物件の現在価格）で順位。

### 2.2 マス
| マス | 効果（`yearScale = 1 + 0.35 × (year − 1)` 倍） |
|---|---|
| 青 | +(8〜20) 億 × yearScale |
| 赤 | −(5〜15) 億 × yearScale |
| 黄 | カード 1 枚 |
| ニュース | イベント抽選（§2.6） |
| 都市 | その都市の物件を購入できる（何件でも、所持金の範囲で） |

### 2.3 物件と経済
- 物件は `price`（億円）と `yieldPct`（年利）。決算時の収益 = `price × yieldPct/100 × 業種倍率 × 特性倍率`、**都市独占（全物件所有）で 2 倍**。
- 業種倍率: `industry_mod` イベントで一時的に変動（複数は乗算、年数で失効）。業種の購入価格は `price_mod` で恒久変動。
- 資金不足: 支払いで所持金が負になったら `sell` フェーズ。物件を売却価格 = 現在価格 × 0.7 で売る。物件が無ければ借金として繰り越し（所持金マイナス）。
- 決算レポート: 各自の収益、総資産、風刺見出し 1 行。
- **買収（`buyout`）**: `buy` フェーズで、その都市の他プレイヤー所有物件を現在価格 ×1.5 で買い取れる。所有者がその都市を独占している場合は ×2.0 で、買うと独占が崩れる。代金は所有者に支払う。**1 訪問につき 1 回**（`Phase.buy.boughtOut`）。買収後も同じ駅で空き物件は買える（手番は終わらない）。CPU は Lv2 以上が「自分の独占完成 / 首位の独占破壊 / 高利回り」で、現金の余力を残して買収する。

### 2.3.1 最終年（`src/core/showdown.ts`）
- 3 年以上のゲームは第 N 年、1 年制のゲームは最終 3 か月（1〜3月）が「最終年／最終盤」。開幕に `final_year` fx を出し、ルール変更を全画面バナーで告知する。
- 最終年は **目的地一番乗りボーナス ×2**、**最終年イベント（`finalYear`）が抽選対象**、**青マス +50%（首位以外）**。
- 最終年を除く各年末決算で、最下位に `underdog` カードを無料配布する。

### 2.4 目的地と「ハーメルンの取り立て屋」
- 目的地一番乗りボーナス = `(30 + 2 × 開始時の最短歩数) × yearScale` 億。次の目的地を抽選（現在地から 20 歩以上離れた都市）。
- 一番乗りが出た瞬間、目的地から最も遠い（最短歩数）プレイヤーに**取り立て屋（笛吹き）**が憑く。
- **変身ルーレット** (`piper_roulette` fx): 新たに憑くとき、姿を抽選する（Lv1 72% / Lv2 ブラック 20% / Lv3 キング 8%）。憑いた手番数 8 で Lv2、16 で Lv3 へ強制エスカレーション。加えて月替わりに、憑かれている相手へ変身ロール（Lv1→2 15%、Lv2→3 10%、Lv3 は 20% で退散 8% / Lv1 に縮小 12%）。
- **被害は純資産（現金＋物件評価額）に比例**する。所持金が足りなければ物件を安い順に強制売却して支払う。
  - Lv1: 純資産の 3〜6%（現金取り立て）／物件 1 件を 2 割で没収／カード 1〜2 枚／ガラクタ情報商材 10 億／1 回休み。
  - Lv2: 数値被害 2 倍・物件 2 件。
  - Lv3: **災害ルーレット** (`piper_disaster` fx、5〜7 種)。一等地の半数の二束三文セール／所持金半分のチャリティー／最高額物件の 2 割叩き売り／地球の裏側へ拉致／カード全没収＋保管料／全物件キング税。1 回の被害は純資産の 35% を上限にし、超過分は現金で返る。さらに 10% で借金地獄送り。
- **弁護士軍団 (`shield`)**: Lv1/Lv2 は丸ごと無効、キングは被害半減。`piper_charm` は数値被害を半減。
- **気まぐれな善行** (`piper_gift` fx、約 5%): 借金の全額肩代わり／いまいる都市の物件を勝手に購入／現金を置いていく。
- **1 回休みの示談**: 人間の手番で 1 回休みのいたずらを引くと、既存の `event` フェーズで 2 択（休む／示談金 = 純資産の 5%、ブラックは 10%）を出す。CPU は `cpuDecide` で現金で払えるなら払う。イベント定義は `src/core/piperLines.ts` の `PIPER_DEAL_EVENT`（抽選対象外、`weight: 0`）。
- **すれ違い**: 移動中に他プレイヤーのいるマスを通過・停止すると、取り立て屋はその相手へ移る（移動した人が holder の場合のみ）。**姿（レベル）はそのまま移動する**。`piper_pass` カードも同じ。
- CPU Lv2/Lv3 は、憑かれているときは他プレイヤーのマスを通る進路を好み、憑かれていないときは Lv2/Lv3 の holder の近くに止まる進路を避ける（`src/core/piperCpu.ts`）。

### 2.6 イベント（`events.json`）
- ニュースマスで、重み `weight`・`minYear`・`once` を満たすものから抽選。
- `lines` を順に再生 → `choices` があれば現在プレイヤーが選ぶ（オンラインでは他の人も同じ画面を見る）→ `reply` 再生 → 効果適用。
- `kind`: `news`（現実のニュースが元）/ `history`（歴史的事実が元）/ `fable`（完全創作）。news/history は `fact`（風刺を含まない事実要約）と `sources` 必須。`satireNote` でどこが誇張・創作かを示し、ゲーム内の「元ネタ」ボタンで表示。
- 実在の存命人物は名前・似顔絵で出さず、役割の戯画（「関税おじさん」等）にする。
- 話者は `narrator` / `npc:<id>` / `char:<id>`。**`self` はイベントで使わない**（全キャラ分の音声生成を避ける）。手番キャラの反応は `Fx say` + `lineKey` で行う。

### 2.7 キャラクター特性（`PerkId`）
型定義のコメント通り。各キャラに 1 つ。強さは控えめで、選ぶ楽しさを優先。

### 2.8 CPU
- Lv1: 目的地へ近づく移動のみ、物件はランダム、カードはほぼ使わない。
- Lv2: 目的地への最短歩数を最小化する移動、利回り順で現金の 30% を残して購入、カードを状況で使用。
- Lv3: Lv2 + 独占狙い、取り立て屋のすれ違い押し付けを狙う移動、イベント選択の期待値評価。

## 3. エンジン API（`src/core/engine.ts`）

```ts
createGame(data: GameData, config: GameConfig): StepResult
step(data: GameData, state: GameState, playerId: number, action: Action): StepResult // 不正なら EngineError を throw
actorOf(state: GameState): number | null  // 今行動すべきプレイヤー（game_over なら null）
cpuDecide(data: GameData, state: GameState): Action // actorOf の席の CPU 判断（autoplay にも使う）
netWorth(data: GameData, state: GameState, playerId: number): number
currentPrice(data, state, propertyId): number
annualIncome(data, state, playerId): number
distance(data, fromNodeId, toNodeId): number // 最短歩数（BFS, キャッシュ）
sanitizeState(state): Omit<GameState, 'rng'> & { rng: 0 }
```
- 状態は**不変扱い**（`step` は新しい state を返す。`structuredClone` 可）。JSON シリアライズ可能であること（保存・配信・再接続）。
- 決定論: 同じ seed と同じ行動列なら同じ結果。

## 4. 通信（`src/net/protocol.ts` が正本）

- 接続: ルーム作成者がホスト（ルーム ID をブラウザで生成）。ゲストは MQTT の受信箱トピックへ `hello` を送り、以後は WebRTC 直結（不可なら MQTT 中継）で `ClientMsg` / `ServerMsg` をやり取りする。「サーバー」は以下すべてホスト端末の `RoomController` を指す。
- 招待 URL: `https://dma-cmyk.github.io/fable-tycoon/?room=<ROOMID>`。ルーム ID は 6 文字（紛らわしい文字を除く英数大文字）。
- ロビー: 席 4 つ（人間 / CPU / 空き）。各自キャラ選択（重複不可）、ホストが年数・制限時間・CPU を設定して開始。開始条件: 人間 1 人以上、合計 2 人以上。
- 進行: サーバーは `step` の結果 `{seq, fx, state, deadline}` を配信。クライアントは fx を順に演出し、終わったら最新 state で操作 UI を出す。CPU / autoplay の手は fx 演出時間の見積もり分だけ遅らせて適用。
- 演出の同期: サーバーは各 fx の標準演出時間（`fxDuration`）の合計を次の締切に加算。クライアントはスキップ／早送り可（自分だけ）。

## 5. 音声
- 話者ごとの規約: `docs/voicevox-licensing.md`。政治的利用を禁止する話者は**この作品では使わない**。クレジットはタイトル画面「クレジット」と README に表示。
- `tools/gen-voice.mjs`: characters.json の lines、events.json / npcs の台詞、ナレーター定型文（都市到着・目的地発表など）を収集 → VOICEVOX `audio_query` + `synthesis` → ffmpeg で mono mp3 → `public/assets/voice/<hash>.mp3` と `manifest.json`（キー = `fnv1a(voiceKey + '\n' + text)`、voiceKey は `char:<id>` / `npc:<id>` / `narrator`）。生成済みはスキップ（差分生成）。
- クライアント: 台詞は字幕を常に表示。音声があれば再生、無ければ字幕のみ。ボリューム（マスター / 声 / BGM / SE）、台詞スキップ、自動送り。

## 6. AI による拡張手順（`docs/CONTENT.md` に詳細）
都市追加 = `cities.json` に追記 → `npm run board` → `npm run validate`。キャラ追加 = 画像 + characters.json → `npm run voice`。イベント追加 = events.json（出典付き）→ validate → voice。

## 8. コミュニケーション（チャット・リアクション・キャラクターアクション）

**原則: 演出専用と妨害を分ける。** チャット・スタンプ・キャラクターアクション（ちょっかい含む）は `GameState` を一切変えない演出専用で、手番に関係なくいつでも使える。ゲーム進行に影響する妨害は**カード**（牛歩法案・敵対的買収・笛の押し付け・関税）だけで、自分の手番にしか使えない。

| 機能 | 仕様 |
|---|---|
| テキストチャット | ロビー・ゲーム中ともに使用可。80 文字まで。発言は順位パネル横と、マップ上の発言者の駒の頭上に吹き出し（4 秒）、チャットログ（直近 60 件、再接続時も復元）。自動読み上げはしない |
| スパム対策 | サーバーでトークンバケット（1.5 秒ごと 1 回、バースト 3）、同一文の 10 秒以内の連投破棄、URL を `[URL]` に置換、NG ワードを `＊` で伏字（`src/net/filter.ts` のリスト）。超過は `rate_limited` で本人にだけ通知 |
| ミュート | クライアント側。席ごとにチャット / エモート / ボイスを個別ミュート（`localStorage`）。全体の「チャットを表示しない」設定も用意 |
| 通報 | `report` を送るとホストが「通報者・対象・理由・対象の直近チャット 10 件・時刻」を記録（ホスト端末の `localStorage`、設定画面から JSON で書き出し可。専用サーバーが無いため運営への自動送信はしない）。同一ルームで 2 人以上に通報された席は他の全員の画面で自動ミュート |
| エモート | `src/data/emotes.json`（`EmoteDef`）。カテゴリ: 喜怒哀楽（emotion）、ダンス・土下座・札束ばらまき・自慢・感謝（action）、挑発・「早くして〜」（taunt）、ちょっかい（poke: 相手を選んで投げ物）、キャラ固有技（unique, 各キャラ 1 つ） |
| 連打対策 | 席ごとにエモート全体 2.5 秒・バースト 2、各エモートの `cooldownMs`。クライアントは同じ席の演出を 1 つずつ再生し、待ちが 2 件を超えたら古いものを捨てる。エモートはモーダルを出さず、操作 UI・入力を塞がない（重ね描きのみ） |
| ボイス連動 | エモートは発動キャラの台詞（`lines[characterId]` または `default`）を、そのキャラの声で事前生成して再生。ちょっかいは当てられた側の `hitLines` 返し台詞も再生。ゲーム進行の台詞（イベント・ナレーション）を優先し、エモート音声は別チャネルで最大 1 本、ゲーム音声再生中は音量を下げる |
| 同期 | サーバーが `EmoteEvent`（id, seat, emoteId, target, at）を全員へ配信。各クライアントは受信順に再生。台詞の字幕・音声・アニメは同じ開始時刻で再生 |
| CPU の賑やかし | CPU 席は特定の fx（赤マス・目的地一番乗り・取り立て屋・独占・決算）に確率で反応エモートを出す（同じレート制限に従う） |
| 拡張 | エモート追加 = `emotes.json` に追記（アニメは `EmoteAnim` の語彙から選ぶ）→ `npm run validate` → `npm run voice`。新しいアニメ語彙が必要な場合のみ `MapView.playEmote` に実装を足す |
| 将来の公開マッチング | 公開ルームでは自由入力チャットを既定で無効（定型文とエモートのみ）にする設定 `RoomSettings.freeChat` を追加予定 |

## 10. 異世界マップ（天国・地獄・宇宙）

地上の世界地図とは別の小さな盤面。イベント・カード・特殊マスで送られ、出口（`portal`）まで進むと地上へ戻る。定数とマス倍率は `src/core/realm.ts`。

| realm | 名前 | 盤面 | 行き方 | 特徴 | 出口の行き先 |
|---|---|---|---|---|---|
| `heaven` | 天下り天国 | 雲の上。駅 5（雲の上の豪邸・天使投資ファンド等、高価格・高利回り）、マス約 30 | エンジェル投資家イベント、竜巻マス 5%、目的地一番乗り 3 回目のごほうび | 青マス ×3、赤マス ×0.5 | 目的地から 5〜10 歩の都市 |
| `hell` | 借金地獄 | 溶岩と閻魔の税務署。駅 5（地獄の釜ゆで温泉・針の山スキー場等、安いが高利回り）、マス約 36、出口は遠い「蜘蛛の糸」 | 借金地獄イベント（所持金マイナス時に発生しやすい）、キング取り立て屋の悪さ、竜巻マス 5% | 赤マス ×3、青マス ×0.5、地獄専用ニュース（閻魔の税務調査など） | ランダムな地上の都市 |
| `space` | 宇宙ビジネス特区 | 月面基地・火星の分譲地・小惑星採掘。駅 5、マス約 30 | ロケット便カードで「宇宙」を選ぶ、宇宙旅行イベント | 青・赤 ×1.5、資源物件の利回りが高い | 好きな空港都市を選んで再突入 |

- 盤面: `src/data/realms.json` の駅・物件定義から `tools/build-board.mjs` がループ + 分岐の小盤面を生成し、`board.json` に `realm` 付きノードとして追加（座標は `REALM_W × REALM_H` の realm 座標系）。異世界の駅は `cities.json` ではなく生成時に `GameData.cities` へ `realm` 付きで含める。
- 地上との辺は無い。異世界にいる間の「目的地までの距離」は 出口までの歩数 + 出口から目的地への推定歩数 として扱う（取り立て屋の判定・CPU 用）。
- 異世界にいても月日・決算・取り立て屋・カードは通常どおり。異世界の物件も決算で収益を生み、独占できる。
- `Effect` `{op:'realm', who, realm}` で送る / `'world'` で戻す。`warp` fx の `via: 'realm'`。
- 描画: 手番プレイヤー（またはカメラの追従対象）がいる realm の背景画像と盤面を表示し、画面上部に realm の帯（「☁ 天下り天国」など）。地上 / 天国 / 地獄 / 宇宙 を切り替えて見られるタブを全体マップに置く。
- 音: realm ごとの BGM（`realm_heaven` / `realm_hell` / `realm_space`）。

## 11. マップの見やすさ（ユーザー指摘 2026-11-23「シンプル過ぎ」「窮屈で分かりにくい」）

- **デフォルメ変形**: Miller 図法の上に、駅の密度で決めた滑らかな拡大変形（密度均等化カートグラム）をかける。欧州・日本・東アジア・北米東部などの過密地域を 1.5〜2.3 倍に広げ、海洋やシベリア・サハラを圧縮。格子 `src/data/warp.json`、`geo.ts` の `project()` が適用（`projectRaw()` は変形前）。盤面生成・陸地・地形テクスチャ・川・国境・ラベルはすべて同じ変形を通す。
- **間隔**: ノード同士の最小距離 60、マス間隔 70〜90（変形後のマップ単位）。通常プレイ時は隣接マスが円盤直径の 2.5 倍以上離れて見えるズームで手番プレイヤーを追従。
- **例外（2026-11-24 確定）**: 実在の位置関係を保つため、陸続きで近い駅同士（長崎–鹿児島、大阪–奈良など 33 組）は 60 未満を許容する（`validate-data` は警告）。駅とマス、マスとマスは 60 以上を必須とする。地上ノード数は当初目標の 2,600〜3,200 ではなく、読みやすさを優先した約 1,000（800 未満はエラー）とする。近い駅は、移動候補の番号付き一覧からも選べる。
- **作り込み**: Natural Earth（パブリックドメイン）由来の地形テクスチャをイラスト調に加工（砂漠・森林・ツンドラ・雪・山の陰影）、湖・主要河川・国境・海洋名と国名の日本語ラベル、浅瀬の帯、コンパス、クジラ等の海の飾り。地形スタンプと駅周りの街並み。
- **ミニマップ**: 世界全体とプレイヤー位置・目的地を常時表示し、タップでその場所へ移動。
